# 技術用語を訳しすぎない

日本語で技術文書を書くときに、英語のまま置くべき技術用語を辞書的な日本語に訳し替えてしまうクセ。語彙レベルのAI臭のうち、ソフトウェア・インフラ・AWS・セキュリティの文章でだけ出る系統。一般的な語彙のクセは `phrases.md` を参照。

## 対象範囲

ソフトウェアやインフラについて日本語で書く場所すべて。チャットの返答、計画、コードレビュー、コミットメッセージ、PRのタイトルと本文、コードコメント、ドキュメント。

## 原則

エンジニアが実際に英語で口にする語は、英語のまま置く。地の文は普通の日本語で書き、技術用語(多くは名詞)だけ英語で残す。文ごと英語にするのではない。

| | 例 |
|---|---|
| 使う | この Lambda は cold start が長いので、provisioned concurrency を検討してください |
| 避ける | この Lambda は初期起動遅延が長いので、事前確保済み同時実行数を検討してください |

辞書の上では正しくても、誰も口に出さない語に置き換わると、読み手はそれを英語に戻してから読むことになる。この戻すコストは母語によってばらつくので、英語のまま置くほうが共通の足場になる。AWSのドキュメントもAPI名もエラーメッセージも英語なので、英語のままのほうが検索も引き継ぎも早い。

## 判断手順

用語ごとに、上から順に判断する。

1. リポジトリの慣習が最優先。コードベース、そのドキュメント、編集中のファイルの周辺がすでにどちらかで統一されているなら、それに合わせる。日本語表記で統一されているならそちらを使う。何かを決める前に、まず既存の表記を確認する。
2. 定着した英語のジャーゴンは英語のまま置く。rate limiting、allowlist、source map、payload、cold start、blast radius、remote state、subscription filter、hot path、silent failure、backpressure、idempotency など。
3. 英語と日本語のどちらも定着しているなら、計画やレビューでは英語を選ぶ。レート制限より rate limiting、再試行より retry。ただし技術文書にたまたま出てくるだけの普通の日本語(設定、権限、検証)は日本語のまま。これはジャーゴンの話であって、名詞すべての話ではない。
4. 定着した日本語がないなら英語を使う。造語しない。

## 造語しない、持ち込まない

このクセのいちばん厄介な出方が造語。既存の語を選び間違えたのではなく、存在しない語を作ってしまうので、読み手は辞書でもコードベースでも照合できない。

- 直訳の造語を作らない。限流(rate limiting)、許可名簿(allowlist)、積載物(payload)は日本語ではない。日本のエンジニアが実際に使っている語を思い出せないなら、それはその語が存在しない証拠だと考えて、英語で書く。
- 類推で熟語を組み立てない。日本語は 非 や 不 で否定する語であって、有 と 無 の対で作る語ではない。有界の対義語は非有界であって、無界ではない。
- 漢字が共通しているからといって、中国語や韓国語の語を持ち込まない。中国語の語を日本語の漢字表記に置き換えたものは、語彙ではなく誤りとして読まれる。逆方向も同じ。
- 英語でだけ正確な語を訳さない。bounded / unbounded、eventual consistency、at-least-once のように、日本語にすると不自然か曖昧になるものは英語のまま置き、読み手に必要なら括弧で短い日本語の補足を添える。
- 不自然な造語と、平易な説明の日本語で迷ったら、平易な日本語を選ぶ。無界より「影響範囲に上限がない」のほうがまだ読める。チームが英語で言っている語なら、英語がその両方に勝つ。

## そのまま訳さない

次のものは原文のまま再現する。訳さない、直さない、整えない。

- 識別子、型名、API名
- CLIのフラグ
- 設定キー
- ファイルパス
- 環境変数
- エラーメッセージ
- ログ出力

原文を引用したうえで日本語で説明を添えるのは問題ない。`--flag` を訳したり、エラー文字列を言い換えたりするのが問題になる。

## 横文字メタファーとの境界

`phrases.md` の「横文字メタファー」「過剰なカタカナ表記」と、このルールは方向が逆に見えるが、原則はひとつしかない。エンジニアが実際に口にする形に寄せる、それだけ。

| | 直す対象 | 直す方向 |
|---|---|---|
| 横文字メタファー、過剰なカタカナ | 日本語で言えるのにカタカナで書いている | カタカナ → 日本語 |
| 技術用語の訳しすぎ | 英語で言うのが普通なのに訳している | 日本語 → 英語 |

思考のOS、人生をハック、アライメント、コミュニケーションは日本語に戻す。cold start、payload、idempotency は英語に戻す。判断が割れたら、その語を会話で口に出すかどうかで決める。

## セルフチェック

見慣れない技術的な熟語を含む日本語を出す前に、ひとつだけ確認する。

この語を、チームの日本人エンジニアが朝会で口に出して言うか。

言わないなら、英語の用語に置き換えるか、平易な説明の日本語に書き換える。
