# 視覚設計の作り込み

実装は `assets/tokens.css` です。この文書は、そのトークンをどう使えば専業の設計者が作ったものに見えるかの規範です。

既定の外観は第12節の「没入型」です。暗色を地とし、内容に彩度を持たせ、骨格を無彩に寄せる型です。情報密度を優先する画面では第12節の手順で「実務型」へ切り替えます。

---

## 1. なぜ既定のまま作ると淡白になるのか

淡白さは、判断していない箇所の集積です。既定値をそのまま使うと、すべての要素が同じ視覚重量になり、階層が消えます。階層が消えた画面は「情報が並んでいるだけ」に見えます。

作り込まれた画面との差は、装飾の量ではなく判断の量です。次の8種の判断をすべて行います。階調のどの段を使うか、活字のどの役を当てるか、間隔をどの刻みにするか、何を主役にするか、状態をいくつ描き分けるか、動きに何秒かけるか、数値をどう揃えるか、密度を用途に合わせるか。

この文書は削る側の規範が中心です。削るだけでは無個性になるため、何に投資するかを第13節に、どの方向へ振るかを `visual-styles.md` に置いています。3つを合わせて使います。

---

## 2. 階調は12段の役割で選ぶ

段を「濃さ」で選ばず「用途」で選びます。

| 段 | 用途 |
|---|---|
| 1 | 画面の地 |
| 2 | 控えめな面（縞、コードブロック、側面領域） |
| 3 | 部品の面（通常） |
| 4 | 部品の面（hover） |
| 5 | 部品の面（押下・選択） |
| 6 | 非対話要素の罫線と区切り（側面領域、見出し帯、カード、区切り線） |
| 7 | 対話要素の枠、フォーカスリング |
| 8 | 対話要素の枠（hover） |
| 9 | 塗り。最も純度が高く、主要操作と図形に使う |
| 10 | 塗り（hover） |
| 11 | 低対比の文字。灰は補足文字として淡く、意味色は必ず読ませる文字として濃い |
| 12 | 高対比の文字 |

守るべき組み合わせの規則です。

- 面には 1〜5 を使い、文字には 11〜12 を使います。面に 6〜8 を使うと枠と区別できなくなります。
- 罫線に 3 や 4 を使いません。薄すぎて構造が読めません。逆に 9 以上を使うと線が主役になります。
- 強調色の 9 の上に載せる文字は専用に決めます。強調色の色相によっては暗い文字が必要です。
- 灰の色相を強調色と同系へわずかに寄せると調和します。無彩色にすると機能的な印象になります。用途で選びます。
- 意味色（危険・注意・成功）は 9 / 10 / 11 の3段だけ持ちます。12段すべては要りません。
- 段11は灰と意味色で明度が違います。灰（`--l-muted`）は読み飛ばせる補足文字なので `budgets.json` の `contrast.secondaryText` を基準に淡くし、意味色（`--l-11`）は必ず読ませる文字なので `contrast.text` を満たします。本文との明度差が階層を作るため、灰の段11を濃くすると補足が本文と同じ重さに見えます。

構造を作る手段は外観プリセットで変わります。実務型では枠が構造を作り、影は浮いているものだけに使います。没入型では面の明度差（段1と段2と段3の差）が構造を作り、枠線は意味のある1本に限ります。いずれも影は3段までです。

## 3. 活字は役で当てる

寸法を都度選ばず、役に対応させます。基準寸法は用途で2つに分けます。

| 体系 | 基準 | 使う場面 | 見出し |
|---|---|---|---|
| productive | 14px | 一覧、表、管理画面、設定 | 固定寸法。器の中に収まることを優先する |
| expressive | 16px | 読み物、着地ページ、説明 | 流体。小画面と大画面で別の階比を持たせ補間する |

役と当て方です。

| 役 | 寸法 | 行間 | 字間 |
|---|---|---|---|
| 画面見出し | `--text-3xl` または `--text-4xl` | tight | tight |
| 区画見出し | `--text-xl` または `--text-2xl` | tight | snug |
| 小見出し | `--text-lg` | snug | normal |
| 本文 | `--text-md` | normal | normal |
| 補足 | `--text-sm` | snug | normal |
| ラベルと注記 | `--text-xs` | snug | wide |

寸法が上がるほど字間を詰め、下がるほどわずかに開きます。すべて同じ字間にすると、大きい文字が緩んで小さい文字が詰まって見えます。

太さは3段までにします。通常、中太、太。すべての見出しを太字にすると階層が消えます。寸法と色（11 と 12 の差）でも階層は作れます。

日本語では英字向けの行間が詰まって見えます。本文の行間は 1.7 前後を基準にします。

Inter を使う場合は光学サイズを有効にし、合字と文脈依存の異体を有効にします。

## 4. 数値は揃える

数値を含む画面では、比例数字のままにすると桁がずれて比較できません。

| 対象 | 規則 |
|---|---|
| 表や一覧の数値 | `font-variant-numeric: tabular-nums` を当て、右揃えにする |
| 通貨と単位 | 数値より1段落とした色（11）と寸法にする。数値が主役 |
| 増減 | 記号と色で方向を示し、色だけに頼らない |
| 桁区切りと通貨 | `Intl.NumberFormat` に任せる |
| 0 と o の混同が問題になる場面 | スラッシュ付きゼロの字形を有効にする |

## 5. 間隔でリズムと階層を作る

間隔は刻みから選びます。刻みの外の値を使いません。

近接が関係を作ります。近いものは関係があると見え、離すほど関係が弱く見えます。同じ間隔で並ぶものは同じ重みだと見えます。したがって、関係のない要素を等間隔で並べません。

余白が階層を作ります。周囲の余白が多い要素は重要に見えます。見出しの上の余白を下より広く取ると、見出しが次の段落に属していることが読めます。

区切り線を引く前に、余白で分けられないかを試します。線は最後の手段です。

## 6. 階層を1つ作る

1つの画面に主要操作は1つです。塗り（9）のボタンが2つ以上ある画面は、どちらが主役か決めていない画面です。副操作は枠のみ、三次操作は文字のみにします。

視覚重量に差を付けます。同じ寸法・同じ色・同じ太さの要素が並ぶと、目の入口がなくなります。

密度を用途に合わせます。データを比較する画面に余白を多く取ると、一覧性が落ちて逆に読みにくくなります。読み物に密度を上げると疲れます。

## 7. 状態を描き分ける

hover だけ用意して終わりにしません。次を別物として設計します。

外観プリセットで表現の手段が変わります。実務型は枠を、没入型は面を主に使います。

| 状態 | 実務型 | 没入型 |
|---|---|---|
| 通常 | 面3、枠7 | 面3（枠なし） |
| hover | 面4、枠8 | 面4 |
| 押下 | 面5 | 面5 |
| フォーカス | フォーカスリング。hover と兼用しない | 同じ |
| 選択 | 面5＋強調色の枠。hover と区別できること | 同じ |
| 無効 | 不透明度を落とし、理由を添える | 同じ |
| 読込中 | 寸法を保った骨組み。差し替え時に配置が動かないこと | 同じ |

## 8. 動きは距離に比例させる

同じ所要時間を全部に使いません。

| 対象 | 時間 |
|---|---|
| ボタンや切替の反応 | 70ms |
| 淡い出現と消失 | 110ms |
| 小さな展開、短距離の移動 | 150ms |
| 展開、通知 | 240ms |
| 大きな展開、重要な通知 | 400ms |
| 背景の減光 | 700ms |

曲線は入りと出で変えます。入りは減速のみ、出は加速のみ、往復は標準曲線です。日常の操作は productive の曲線、節目の演出は expressive の曲線を使います。

`transition-all` を使いません。変える性質だけを指定します。全性質の監視は描画負荷になり、意図しない性質まで動きます。

`prefers-reduced-motion` を尊重します。

## 9. アイコンと図形

| 規則 | 内容 |
|---|---|
| 絵文字をアイコンに使わない | 環境で字形が変わり、線幅と光学寸法が本文と揃わない |
| 線幅を揃える | 1つの体系の中で線幅を混ぜない |
| 寸法を揃える | 本文に添えるなら文字の寸法に対する比で決める |
| 意味のない装飾を足さない | 図形は情報を運ぶ場合にのみ置く |
| 装飾のためのグラデーションを使わない | 面の階調で十分。使うなら意味（深度、進捗）を持たせる |

## 10. 避ける既定の癖

### 10-1. 淡白に見える癖

生成された UI が淡白に見える具体的な原因です。実装後にこの表で自己点検します。

| 癖 | なぜ淡白に見えるか | 代替 |
|---|---|---|
| 汎用パレットの直用い（`gray-*`、`slate-*`、`bg-white`） | 段の用途が決まっておらず、面と枠と文字の役割が混ざる | 12段の用途割り当てを使う |
| 全要素が同じ角丸・同じ枠・同じ余白のカード | 視覚重量が均一で階層が消える | 主役の器だけ影と余白を持たせ、従属要素は罫線のみ |
| 絵文字をアイコン代わりに置く | 本文と線幅も光学寸法も揃わない | 線幅を揃えたアイコン体系を使う |
| 区画を縦一列に積んで中央寄せする | 基準幅で横方向が余り、密度も用途に合わない | 主題と付随情報を横に並べる。密度は用途で選び、データ画面は詰める |
| 影を装飾として全体に付ける | 浮いているものが判別できなくなる | 影は3段まで。密度の高い画面では枠が主役 |
| 意味のないグラデーション | 情報を運ばない装飾が主役になる | 面の階調で表現する |
| 見出しがすべて同じ寸法と太さ | 階層が読めない | 役に対応した寸法・行間・字間を当てる |
| 比例数字のままの表 | 桁がずれて比較できない | `tabular-nums` と右揃え |
| hover のみ実装 | 触れる前と触れた後の区別しかない | 7状態を描き分ける |
| すべての間隔が同一値 | リズムがなく、関係と階層が伝わらない | 刻みから選び、近接と余白で構造を作る |
| `transition-all duration-300` を一律で当てる | 動きが用途と距離に対応しない | 対象の距離に応じて 70〜700ms を選ぶ |
| 塗りのボタンが1画面に複数 | 主役が決まっていない | 主要操作は1つ。副は枠、三次は文字 |
| 英字向けの行間のまま日本語を組む | 字面が大きいため詰まって見える | 本文 1.7 前後 |
| 単位や通貨を数値と同じ強さで置く | 数値が主役に見えない | 単位は1段落とす |

### 10-2. 生成AIの定型癖

画面が「テンプレートから出てきたように」見える原因は、個々の要素の質ではなく癖の反復です。生成する側の既定の美観は広く知られており、そのまま出すと作り手の判断が入っていないことが伝わります。実装後にこの表で自己点検します。人手判定は `assets/ux-review-checklist.md` の L 節です。

| 癖 | なぜ既製品に見えるか | 代替 |
|---|---|---|
| すべての区画見出しに小さな英大文字のラベルを付ける | 同じリズムの反復がテンプレートの署名になる | 原則付けない。見出しだけで足りる。使うなら3区画に1つまで |
| 等幅3カラムのカード列で特徴を並べる | 最頻出の既定形で、視覚重量も均一になる | 面積差のある格子、1+2の分割、横断1列で主従を作る |
| 画像と文の左右交互を3回以上続ける | パターンの機械的な反復に見える | 3つ目までに全幅・縦積み・格子など別の骨格を挟む |
| 同じ骨格の区画をページ内で繰り返す | 内容が違っても同じ画面に見える | 同一骨格は1ページ最大2回。区画が多いページほど骨格の種類を増やす |
| 装飾のための色付きドット・状態風の点 | 意味のない記号は状態表示の偽装になる | 実際の状態を伝える場合のみ。1画面1箇所まで |
| スクロールを促す文言や矢印 | 利用者はスクロールを知っている | 置かない。続きの存在は要素の見切れで示す |
| div で組んだ偽のスクリーンショット・偽の端末画面 | 偽物と分かった瞬間に画面全体の信頼が落ちる | 実物の画面、実際に動く縮小版、または載せない |
| 紫〜青のグラデーションと光る縁 | 生成AIの既定の美観として広く認知されている | 無彩の骨格と強調色1つ。既定値のまま出さない |
| 装飾のための回転テキスト・飾りの英文ストリップ | 意味を運ばない飾り文字は作り手の不在を示す | 置かない |

### 10-3. 見本データの規範

見本データの質は画面の質に直結します。実装の見本・スクリーンショット・デモに置くデータは次に従います。

- 人名・組織名に「山田太郎」「サンプル株式会社」「Acme」のような見本と一目で分かる名を使いません。ロケールに合う、実在しそうで実在しない名を作ります。
- 「99.99%」「12345」「50%」のような作り物めいた数値を使いません。現実の分布に見える端数を持たせます。
- 実データに由来しない精密な数値を根拠なく置きません。見本である場合はその旨をコメントに残します。

## 12. 外観プリセット

同じトークン体系のまま、2つの外観を切り替えます。`:root` の `data-appearance` で選びます。既定は没入型です。

| プリセット | 属性 | 向く画面 |
|---|---|---|
| 没入型 | 既定（属性なし） | 内容そのものが主役の画面。作品や図表や数値を見せる、閲覧と探索が中心のもの |
| 実務型 | `data-appearance="productive"` | 入力と一覧と設定が中心の画面。情報密度と一覧性を優先するもの |

### 没入型の規範

| 規範 | 内容 |
|---|---|
| 地は近黒 | 画面の地を明度 0.15 前後の近黒にします。灰色ではなく黒に寄せることで、内容が発光しているように見えます |
| 骨格は無彩 | 枠や地や文字といった骨格側の彩度をほぼ 0 にします。彩度は内容（画像、図、数値の増減）が持ちます。骨格が色を持つと内容と競合します |
| 強調色は1つ | 強調色は主要操作と現在位置にのみ使います。1画面に2箇所以上使うと、どこを見ればよいか分からなくなります |
| 強調色を意味色と衝突させない | 強調色の色相を、危険（25前後）・注意（78前後）・成功（152前後）から30度以上離します。ブランドが赤や緑を要求する場合は、意味色側を記号と語でも伝えて区別を確保します |
| 枠より面 | 区切りに枠線を使わず、面の明度差（段2と段3の差）と影で階層を作ります。枠線は表の見出しの下など、意味のある1本に限ります |
| 主役を特大にする | 画面の主題（題名、合計値、現在の状態）を特大寸法で置き、字間を強く詰めます。付随情報は小さく淡くします。この寸法差が階層を作ります |
| 帯で並べる | 一覧は横方向の帯として並べます。帯の中の間隔は詰め、帯と帯の間は大きく空けます。均等な格子に並べると視線の順路が消えます |
| 覆いで可読性を作る | 画像や図の上に文字を載せる場合、下から上へ向かう覆いを掛けます。これは可読性のための機能です。意味のない装飾のグラデーションとは別物です |
| hover は寸法と影で応える | 枠の色を変えるのではなく、わずかに拡大して持ち上げます。倍率は `--lift`（既定 1.02）を使い、1.05 を超えません。それ以上は落ち着きを失います |
| 操作帯を常設する | 再生や選択のような継続する操作は、画面の端に常設した帯へ置きます。文脈を切らないことが目的です |
| 動きは速く、出は減速のみ | 入りは減速のみの曲線、出は加速のみの曲線を使います。所要時間は第8節の表から選びます |

### 実務型へ切り替える条件

外観と密度は直交します。外観は画面の性格で選び、密度は区画ごとに当てます。したがって「一覧が1つある」だけでは実務型にしません。

外観を実務型にするのは、画面の主目的が走査と入力そのものである場合です。次の2つ以上に当てはまるときが目安です。

- 画面の大半が一覧や表で占められている。
- 入力欄が5個以上ある。
- 利用者が1日に何十回も往復する。
- 印刷や書き出しを前提にしている。

主題を見せる画面に密な一覧が1つ含まれる場合は、外観は没入型のままにして、その一覧の区画だけに `data-density="compact"` を当てます。密度の属性は `:root` に限らずどの要素にも当てられます。

実務型では特大寸法を抑え、区画の間隔を詰め、hover の拡大を無効にします。骨格にわずかな色を帯びさせて面の区別を付けます。

### どちらでも守ること

外観を変えても、コントラスト比、操作対象の寸法、状態の描き分け、動きの抑制設定の尊重は変わりません。没入型は暗色が既定になるため、明色テーマと高コントラストテーマでの実測が特に重要になります。

### 様式との関係

外観プリセットは骨格の作り方（面で構造を作るか、枠で作るか）だけを決めます。どの方向へ振るか、たとえば上質に寄せるのか親しみやすさに寄せるのかは決めません。そちらは `visual-styles.md` の様式が担います。両者は直交するため、没入型のままラグジュアリーにもエディトリアルにもできます。

順序は、目的とターゲットとトーンを決める、様式を選ぶ、その様式に合う外観プリセットを選ぶ、密度を区画ごとに当てる、です。

## 13. 何に投資するか

削る規範だけを適用すると、破綻はないが印象に残らない画面になります。次の順で投資します。上ほど費用対効果が高く、下ほど費用がかかります。

| 投資先 | 具体的に何をするか | 効果 |
|---|---|---|
| 主題の寸法 | 画面の主題に `--fs-hero` を当て、字間を強く詰める。付随情報は落とす | 目の入口ができ、階層が一目で読めます |
| 余白の非対称 | 区画間を `--space-9` 以上、区画内を `--space-5` 以下にする。均等に配らない | 関係と階層が余白だけで伝わります |
| 面積の強弱 | 一覧やカードで重要なものの面積を2倍以上にする | 重要度が言葉なしで伝わります |
| 活字の役当て | 見出し・本文・補足で寸法と行間と字間を別々に当てる | 読み物としての質が上がります |
| 状態の描き分け | 通常・hover・押下・フォーカス・選択・無効・読込中を別物として設計する | 触ったときの手応えが変わります |
| 動きの距離比例 | 第8節の表から対象ごとに所要時間を選ぶ | 操作が機敏に感じられます |
| 写真と図の質 | 明度と彩度と画角を揃える。揃えられないなら使う点数を減らす | 素材の寄せ集め感が消えます |

投資しないものも決めます。装飾のグラデーション、意味を運ばない図形、全要素に付ける影、`transition-all`。これらは費用がかかるうえに印象を下げます。
