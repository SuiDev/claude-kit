# 様式とトーン

数値は `budgets.json`（プロジェクトでは `e2e/budgets.json`）、変数は `assets/tokens.css` が単一情報源です。この文書は既存の変数へどう値を入れるかだけを書きます。

---

## 1. なぜ様式を決めないと安っぽく見えるのか

安っぽさの正体は、装飾の不足ではなく方向の不在です。着手前に次の4つを言語化します。1つでも空欄なら、その画面は既定値に落ちます。

| 決めるもの | 空欄のまま作るとどうなるか |
|---|---|
| 目的 | 何を目立たせるか決まらず、全要素が同じ重さになります |
| ターゲット | 密度・語彙・寸法の基準がなくなります |
| トーン（採用と回避） | 配色と角丸と影が場当たりになります |
| 様式 | 骨格の作り方が決まらず、既定の外観に落ちます |

「いい感じに」「おしゃれに」「今っぽく」は、この4つのいずれも指定していません。これらの語を受け取ったら、下の手順で具体化してから着手します。

---

## 2. 決める順序

### 2-1. 目的

その画面を見た人に何をしてほしいかを1つ選びます。複数あるなら順位を付けます。

| 目的 | 視覚の方向 |
|---|---|
| 登録・購入・申込を促す | 主要操作を最も目立たせ、判断材料を手前に置きます |
| 信頼を伝える | 整列を厳密にし、色数を絞り、余白を均等に取ります |
| 世界観を伝える | 写真と余白と活字に投資し、文字量を減らします |
| 作業を速く終わらせる | 密度を上げ、装飾を削り、走査経路を最短にします |
| 状態を監視させる | 数値を主役にし、変化と異常を色と記号の両方で示します |

### 2-2. ターゲット

年齢層、習熟度、利用場面、抱えている困りごとを書きます。ターゲットが変われば同じ目的でも作りが変わります。高齢者が主なら寸法と対比を上げ、専門職が毎日使うなら密度を上げます。

### 2-3. トーン

採用する印象と、避けたい印象の両方を書きます。避けたい印象を書かないと、方向は合っていても行き過ぎたものが出てきます。

| 採用する印象 | 主な手段 |
|---|---|
| モダン | 無彩の骨格、詰めた字間、細い罫線 |
| クリーン | 広い余白、色数を絞る、影を減らす |
| プレミアム | 特大の活字、余白を大きく、彩度を落とす |
| ナチュラル | 暖色寄りの灰、彩度の低い意味色、角丸を大きく |
| フレンドリー | 角丸を大きく、活字を丸ゴシック系に、対比をやや下げる |
| シック | 暗色の地、低彩度、細い線 |
| コーポレート | 明色の地、整列の厳密化、寒色の強調色 |
| ポップ | 高彩度、大きな角丸、大きな操作対象 |

避けたい印象の例です。ここに挙げた語は、そのまま回避条件として下の第5節の判定に対応します。

```
安っぽい / 子どもっぽい / 派手すぎる / ごちゃごちゃしている / 古い / よくある感じ
```

形容詞は方向の範囲しか指せません。トーンには具体的な参照物を1つ添えます。参照物とは実在する様式・物・場面です。「老舗大学の講義プリント」「空港の出発案内板」「文庫本の奥付」のような1つの参照物は、形容詞の羅列より多くの判断を運びます。インクは1色、余白は広い、装飾はない、といった値の背後にある理由ごと伝わるためです。

参照物が具体的であるほど、避けるべきものも自動的に決まります。講義プリントは光らず、グラデーションを使いません。回避の印象語に加えて、参照物から導いた「やらないこと」を2〜5個書き出し、プロジェクトの `DESIGN.md` に Do's and Don'ts として記録します。禁止の列挙が長く散漫になるときは、参照物の記述が曖昧である兆候です。参照物を絞り直します。

### 2-4. 様式

第3節のカタログから選びます。1つに絞る必要はなく、2つから3つ組み合わせるのが普通です。

## 3. 様式カタログ

用途と、その様式が失敗したときにどう見えるかを対にしています。失敗の欄が回避条件です。

| 様式 | 骨格の作り方 | 向く用途 | 失敗するとどう見えるか |
|---|---|---|---|
| ミニマル | 余白と活字と写真だけで構成し、装飾を持たない | ブランド、士業、作品集 | 情報量が増えると整理できず、素っ気なく見えます |
| フラット | 平面。影を持たず、面の塗り分けで区別する | 紹介ページ、業務システム | 主役が決まらないと印象に残りません |
| マテリアル | 紙の重なり。影と層で階層を作る | 業務アプリ、管理画面 | 影を多用すると重く、独自性が消えます |
| Bento | 大小のカードを格子に並べ、重要度を面積で表す | 機能紹介、要約画面、SaaS | 同寸のカードが並ぶと単調になります |
| エディトリアル | 大きな見出しと大きな写真と余白。読み物の組み方 | 記事、旅行、美容、ブランド | 操作への導線が弱くなります |
| ダーク | 暗色の地に明るい文字。強調色が映える | 開発者向け、映像、監視画面 | 対比の設計を誤ると読み疲れます |
| コーポレート | 明色の地、厳密な整列、寒色の強調色 | 法人向け、企業情報、採用 | 無難に寄りすぎて記憶に残りません |
| ラグジュアリー | 広い余白、色数を絞る、細い罫線、特大の活字 | 高価格帯、宿泊、宝飾 | 文字が小さく情報が少なすぎて不親切になります |
| ポップ | 高彩度、大きな角丸、大きな操作対象 | 催事、教育、若年層向け | 彩度と角丸が過剰だと安っぽく見えます |
| クレイ | 大きな角丸と柔らかい影で厚みを出す | 趣味、健康、生活 | 幼く見えます |
| ニューモーフィズム | 地と同系色の面を、明暗2方向の影で浮かせる | 実験的な画面 | 対比が足りず、押せるかどうか分かりません |
| グラス | 半透明の面と背景ぼかし | 重ね合わせのある画面、監視画面 | 背景次第で文字が読めなくなります |
| ネオブルータリズム | 太い枠、ベタ影、原色に近い配色 | 個人開発、若年層向け、教育 | 高級感が必要な場面では安っぽく見えます |
| 和モダン | 生成り、墨色、藍色、細い線、広い余白 | 宿泊、飲食、伝統工芸、地域 | 和に寄せすぎると古く見えます |
| オーガニック | 大地色、曲線、不規則な形 | 食品、健康、自然体験 | 素朴すぎて洗練されて見えません |
| レトロ | くすんだ色、生成り、粗い質感 | 喫茶、雑貨、音楽 | 操作の作法まで古いと使いにくくなります |
| ダッシュボード | 側面領域、カード、表、図。密度優先 | 分析、管理、監視 | 優先順位がないと数値の壁になります |
| 写真主体 | 大きな写真と短い言葉 | 旅行、飲食、催事 | 写真の質がそのまま印象になります |
| 図解主体 | 立体的な図や挿絵で仕組みを説明する | 法人向け、業務改善、金融 | 絵柄が揃わないと統一感が消えます |

スキューモーフィズム（現実の質感の模倣）と Y2K（2000年代風の光沢）とサイバーパンク（ネオンと走査線）は、対比とキーボード操作の要件を満たしにくく、既定では採用しません。要件で明示された場合のみ、第5節の判定を全て通すことを条件に使います。

### 3-1. 組み合わせの型

| 組み合わせ | 生まれる印象 | 向く用途 |
|---|---|---|
| ミニマル × Bento | 整理されていて洗練された印象 | SaaS、AI、アプリ紹介 |
| フラット × コーポレート | 清潔で信頼できる印象 | 法人向け、企業情報 |
| ダーク × グラス | 先進的で技術的な印象 | 開発者向け、監視画面 |
| エディトリアル × 写真主体 | 世界観が伝わる印象 | 旅行、美容、生活 |
| ラグジュアリー × ミニマル | 上質で静かな印象 | 高価格帯、宿泊、宝飾 |
| オーガニック × ミニマル | 落ち着いて自然な印象 | 食品、健康 |
| クレイ × ポップ | 柔らかく親しみやすい印象 | 趣味、日記、健康 |
| ダッシュボード × フラット | 機能的で見通しの良い印象 | 分析、管理 |
| クレイ × 写真主体 × 挿絵 | 明るく賑やかで、生活に近い印象 | 日本の消費者向けサービス全般 |

### 3-2. 日本の消費者向けの慣習

国内の消費者向けサービスには、欧米の業務用サービスとは異なる慣習があります。既定の様式（無彩の骨格、強調色1つ、装飾なし）をそのまま当てると、地味で作りかけに見えます。

対象が消費者向けだと判定した場合、次を既定にします。判定は、認証なしで使える画面があること、または対象が特定の職種ではなく一般の生活者であることです。

| 項目 | 業務用の既定 | 消費者向けの既定 |
|---|---|---|
| 地 | 暗色 | 明色 |
| 骨格の彩度 | ほぼ無彩 | わずかに色を帯びる |
| 強調色 | 1色 | 主色と副色の2色まで |
| 角丸 | 小さめ | 大きめ |
| 影 | 罫線を主とし影は最小 | 面を持ち上げる影を積極的に使う |
| アイコン | 操作に必要な箇所のみ | 区画の見出しと一覧の各行にも置く |
| 挿絵 | 使わない | 空状態、導入、完了に置く |
| 図版の面積 | 小さい | 主題の区画で画面の3分の1以上 |

この既定は、走査と入力が主目的の画面には適用しません。同じサービス内でも、公開ページは消費者向け、管理画面は業務用として別々に判定します。

## 4. 様式をトークンへ写す

`tokens.css` の変数に値を入れます。ここに無い様式は、近いものから始めて第5節で検証します。使わない様式の設定を先回りで書きません。

共通して触る変数は次のとおりです。

| 変数 | 意味 |
|---|---|
| `--hue-accent` / `--hue-gray` | 強調色と灰の色相 |
| `--chroma-chrome` | 骨格の彩度の強さ |
| `--l-1` 〜 `--l-12` / `--l-muted` | 12段の明度 |
| `--r-2` 〜 `--r-6` | 角丸 |
| `--elev-1` 〜 `--elev-3` | 影 |
| `--fs-base` / `--fs-hero` | 基準寸法と特大寸法 |
| `--lift` | hover の拡大倍率 |

### 4-1. ミニマル × Bento（既定の没入型に最も近い）

```
--chroma-chrome: 1
角丸は --r-4 を基本にし、カードのみ --r-6
影は --elev-1 のみ。深さは面の明度差で作る
--fs-hero を主題に1つだけ当て、他は --fs-2xl 以下に抑える
カードの面積比は最大のものと最小のもので2倍以上の差を付ける
```

### 4-2. フラット × コーポレート

```
--hue-gray を寒色側（240 前後）へ寄せる
--chroma-chrome: 2
明色テーマを既定にする
角丸は --r-3 まで。--r-6 を使わない
影を持たない。区切りは段6の罫線で作る
--lift: 1（hover で拡大しない）
```

### 4-3. ラグジュアリー × ミニマル

```
--chroma-chrome: 0（骨格を完全な無彩にする）
強調色は主要操作1箇所のみ
角丸は --r-2 まで
影を持たない
--fs-hero を上限まで大きくし、--ls-hero をさらに詰める
区画の間隔は --space-11 以上を基本にする
本文の分量を減らす。文字数が増えるならこの様式を選び直す
```

### 4-4. エディトリアル × 写真主体

```
--fs-base: 1rem（読み物の体系へ切り替える）
--lh-normal: 1.8
本文の一行の長さを全角40文字前後に制限する
写真の上に文字を載せる場合は --scrim-bottom を必ず掛ける
見出しは --fs-3xl 以上、本文との寸法差を3段以上空ける
```

### 4-5. ダッシュボード × フラット

```
:root に data-appearance="productive" と data-density="compact"
--chroma-chrome: 3
角丸は --r-3 まで
影は --elev-1 のみ。区切りは罫線
数値には tabular-nums を当て、右揃えにする
--lift: 1
```

### 4-6. クレイ × ポップ

```
--chroma-chrome: 4
角丸は --r-6 を基本にし、操作要素は --r-full
影は柔らかく広いものを --elev-2 に定義し直す
--fs-base: 1rem
操作対象は --control-lg を基本にする
彩度は上げますが、色数は3色までに抑える（第5節の判定を参照）
```

### 4-7. 日本の消費者向け（クレイ × 写真主体 × 挿絵）

第3-2節の既定を実装に落とした設定です。目的が登録や購入で、対象が一般の生活者の場合の出発点にします。

```
明色テーマを既定にする（:root[data-theme='light'] を初期値として与える）
--chroma-chrome: 4（骨格をわずかに色付ける）
--hue-accent は主色。副色は意味色と30度以上離した第2の色相を1つだけ追加する
角丸は --r-6 を基本にし、器は --r-6、操作要素は --r-full
影は --elev-2 を基本にする。カードは常時 --elev-1、hover で --elev-2
--fs-base: 1rem
--lift: 1.02（hover でわずかに持ち上げる）
主題の区画に図版を置き、画面の3分の1以上の面積を与える
区画の見出しと一覧の各行にアイコンを置く
空状態・導入・完了に挿絵を置く
```

副色を持つ場合、塗りの主要操作は主色のみに使います。副色は見出しの装飾、選択中の表示、図表の第2系列に使い、操作には使いません。操作の色が2つあると、どちらが主要な行動か読めなくなります。

### 4-8. 和モダン

```
--hue-gray を暖色側（70 前後）へ寄せる
--chroma-chrome: 2
明色テーマを既定にし、地を生成り（--l-1 を 0.97 前後）にする
角丸は --r-2 まで
影を持たない。区切りは段6の細い罫線1本
--space-11 以上の余白で区画を分ける
```

## 5. 安っぽく見える判定

様式を選んだあと、実装物をこの表で点検します。左の条件に当てはまると、様式が何であれ安く見えます。`ux-review-checklist.md` の J に人手判定の項目があります。

閾値は業務用と消費者向けで変わります。消費者向けで業務用の閾値を当てると地味になり、業務用で消費者向けの閾値を当てると散らかります。第3-2節の判定に従って列を選びます。

| 条件 | 業務用の上限 | 消費者向けの上限 |
|---|---|---|
| 色数（骨格の灰を除く） | 4色 | 6色 |
| 彩度の高い色が占める画面面積 | 15% | 30% |
| 角丸の種類 | 2種類 | 3種類 |
| 影の段数 | 3段 | 3段 |

上限を超えた場合の対処です。

| 条件 | なぜ安く見えるか | 対処 |
|---|---|---|
| 色数が上限を超える | 統制されていない印象になります | 強調色は主色と副色まで、意味色は必要なものだけに絞ります |
| 彩度の高い色の面積が上限を超える | 主役が決まっていないように見えます | 塗りの主要操作を1つに絞り、残りを面か枠に落とします |
| 角丸が上限を超える | 部品ごとに作られたように見えます | 器の角丸、操作要素の角丸、図版の角丸に整理します |
| 影が3段を超える、または全要素に付いている | 浮いているものが判別できません | 影は3段まで。密度の高い画面では罫線を主役にします |
| 文字の太さが4段以上ある | 階層が読めません | 通常・中太・太の3段までにします |
| 見出しと本文の寸法差が1段しかない | 階層が無いように見えます | 2段以上空けます |
| 区画の間隔が本文の行間と同程度 | 情報が団子になります | 区画間は `--space-9` 以上を基本にします |
| 主題が `--fs-xl` 以下 | 目の入口がありません | 主題に `--fs-3xl` 以上を当てます |
| 装飾のグラデーションがある | 情報を運ばない要素が主役になります | 面の階調に置き換えます。次の例外に当たる場合は該当しません |
| 絵文字をアイコンに使っている | 線幅と光学寸法が本文と揃いません | 線幅を揃えたアイコン体系を使います |
| 塗りの主要操作が1画面に複数ある | どれが主役か決まっていません | 主要操作は1つ。副は枠のみ、三次は文字のみにします |
| 全カードが同寸で並んでいる（Bento を選んだ場合） | 重要度の差が表現されていません | 面積比で2倍以上の差を付けます |
| 写真の質が揃っていない（写真主体を選んだ場合） | 素材の寄せ集めに見えます | 明度と彩度と画角を揃えます。揃えられないなら様式を変えます |

### 5-1. グラデーションの例外

次のいずれかに当たる場合は、情報を運んでいるため装飾に該当しません。それ以外は使いません。

| 例外 | 何を運んでいるか |
|---|---|
| 画像や図の上に文字を載せるための覆い（`--scrim-bottom`） | 可読性 |
| 進捗や達成度の表示 | 量 |
| 主題の区画の地に敷く、主色から副色への1段の変化 | ブランドの識別。消費者向けで副色を持つ場合のみ |
| 一覧の末尾で内容が続くことを示す減衰 | 続きがあること |

主題の区画の例外を使う場合、その上に載る文字のコントラストを両端の色それぞれで測ります。中間色だけを測ると端で基準を割ります。

### 5-2. 機械検査との分担

`scripts/ux-lint.sh` が検出するのは、トークンを迂回した色と寸法と影と角丸の直書き（UX01 / UX02 / UX20）、汎用パレットの直用い（UX18）、装飾のグラデーション（UX21）、絵文字のアイコン利用（UX22）、塗りの主要操作の重複（UX24）です。

色数の総数、角丸の種類数、影の段数、彩度の面積比、寸法差、面積比、写真の質は機械検査の対象外で、`ux-review-checklist.md` の K で人手判定します。

## 6. 基準寸法と画面幅の適用条件

読み物と公開ページは `--fs-base: 1rem`、一覧と表と設定画面は `--fs-base: 0.875rem` です。日本語の本文行間は 1.7 前後で変えません。

画面幅は机上ブラウザを基準幅として狭い幅を上書きで足します。要件に携帯端末が主要経路と明記された場合のみ携帯端末起点へ切り替えます。判断は `ux-implementation.md` 第3節です。
