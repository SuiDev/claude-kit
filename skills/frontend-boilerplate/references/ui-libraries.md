# 部品ライブラリと素材

`stack-and-conventions.md` 第2節で採用を決めた道具を、実際にどう使うかの規範です。バージョンはこの文書に書きません。Phase 2 で `npm view` により確認します。

---

## 1. 自前実装が下書き感を生む

部品を自前で書くと、動く最小限のものはできますが、実務で必要な細部が抜け落ちます。抜けるのは、キーボード操作の全経路、フォーカスの閉じ込めと復帰、読み上げの役割と関係、複数の開閉が重なったときの階層、外側の押下による閉じ、`Esc` の扱い、画面端での位置補正です。

これらは仕様として存在は知られていても、実装すると1部品あたり数百行になります。省略すると、見た目は揃っていても触った瞬間に作りかけだと分かります。下書き感の主因は装飾の不足ではなく、この細部の不在です。

したがって、下の表にあるものを自前で書きません。

| 自前で書かないもの | 使うもの |
|---|---|
| 重ね合わせ（ダイアログ、抽斗、ポップオーバー、ツールチップ、文脈メニュー） | shadcn/ui が生成する部品。基盤は Radix UI |
| 選択（選択メニュー、組み合わせ入力、日付選択、単一選択、複数選択、切替） | 同上 |
| 開閉と切替（アコーディオン、タブ、折りたたみ） | 同上 |
| 通知（トースト） | shadcn/ui が採用している通知部品 |
| 表（並び替え、絞り込み、列の表示切替、ページング） | TanStack Table と shadcn/ui の表部品の組み合わせ |
| アイコン | アイコンライブラリ。第3節 |
| 図表 | 図表ライブラリ。第5節 |

自前で書いてよいのは、意味と配置だけを担う薄い部品です。Button、Field、Card、AsyncBoundary、GuardedAction のような、状態と関係の管理を持たないものです。

## 2. 部品ライブラリ

shadcn/ui はコード生成型です。依存として抱えるのではなく、生成物が自分のコードになります。したがって次の扱いをします。

| 項目 | 規約 |
|---|---|
| 導入 | Phase 6 で初期化し、必要な部品だけを生成する。全部品を先回りで生成しない |
| 配置 | 生成物を `shared/components/` の層へ振り分ける。単独で意味を持つものは atoms、組み合わせて意味を持つものは molecules |
| 変数の接続 | 生成物が期待する変数名への別名を `ui-baseline.md` 第1節の層で与える。生成物の中の色指定を書き換えない |
| 改変 | 見た目の調整は variant の追加で行う。振る舞いの実装には触れない。触ると更新時に差分が追えなくなる |
| 追加生成 | 新しい部品が必要になった時点で生成する。使わない部品を置かない |

Radix UI のプリミティブを直接使うのは、shadcn/ui に該当する部品がない場合だけです。その場合も配置と変数の接続は同じ規約に従います。

## 3. アイコン

アイコンの不在は下書き感に直結します。操作の意味を文字だけで伝える画面は、情報量が同じでも未完成に見えます。

| 項目 | 規約 |
|---|---|
| 体系 | 1つのライブラリに統一する。shadcn/ui と組み合わせる場合は Lucide を既定とする |
| 混在 | 複数のライブラリを混ぜない。線幅と光学寸法が揃わない |
| 寸法 | 本文に添えるものは文字寸法に対する比で決める。単独の操作要素では 16px か 20px を基本にする |
| 線幅 | 体系の既定値から変えない。変えるなら画面全体で変える |
| 色 | 単独では段11、操作要素の中では親の文字色を継承させる |
| 絵文字 | アイコンの代わりに使わない。環境で字形が変わり、線幅と光学寸法が本文と揃わない |
| 装飾目的 | 意味を運ばないアイコンを置かない。情報を伝えるか、操作を示す場合にのみ使う |

配置する場所の目安です。ここが空だと下書きに見えます。

- 主要な操作（保存、追加、削除、共有、絞り込み、並び替え）
- 移動の導線（側面領域、タブ、パンくず）
- 状態の表示（成功、警告、危険、読込中）
- 空状態と誤り状態の中心に置く図
- 一覧の各行が持つ種別の区別

## 4. 動き

動きのライブラリは、CSS の遷移で表現できないものにだけ使います。要素の出入り、並びの入れ替え、掴んで動かす操作、経路をまたぐ遷移が該当します。hover や押下の反応は CSS の遷移で足ります。

| 項目 | 規約 |
|---|---|
| 採用 | Motion（旧 Framer Motion）を既定とする |
| 読み込み | 使う画面でのみ動的 import する。初期ロードに載せない |
| 所要時間 | `visual-craft.md` 第8節の表から選ぶ。ライブラリの既定値を使わない |
| 抑制設定 | `prefers-reduced-motion` を尊重する。ライブラリの機能で一括制御する |
| 寸法予算 | 初期 JavaScript の予算は `budgets.json` の `bundle` にある。動的 import しない場合は予算を超えるため、`verify.sh` が落ちる |

動きを入れない判断も同じだけ正当です。走査と入力が主目的の画面では、動きは待ち時間として体感されます。

## 5. 図表と素材

| 用途 | 使うもの | 注意 |
|---|---|---|
| 図表（棒、折れ線、円、面） | shadcn/ui の図表部品。基盤は Recharts | 色は強調色と意味色から採る。既定の配色を使わない |
| 挿絵 | ライセンスが明確な SVG の組を1つ選び、体系を統一する | 複数の組を混ぜない。絵柄が揃わないと寄せ集めに見える |
| 写真 | 明度・彩度・画角を揃える。揃えられないなら点数を減らす | 文字を載せる場合は `--scrim-bottom` を掛ける |
| 空状態の図 | 挿絵かアイコンを中央に置く。文字だけで済ませない | 何が入る場所かと最初の一歩を併記する |

素材を置かない選択をした場合、余白と活字で密度を作ります。図版も余白の設計もない画面が最も下書きに見えます。

---

## 6. 導入の順序

Phase 6 で次の順に入れます。先に部品ライブラリを入れてからトークンを接続すると、生成物の色指定を書き換える作業が発生します。

1. トークンを配置する（`ui-baseline.md` 第1節）
2. 生成物が期待する変数名への別名を与える
3. 部品ライブラリを初期化する
4. その画面で使う部品だけを生成する
5. アイコンライブラリを入れる
6. 動きと図表は、必要になった画面で入れる

各ライブラリのインストールは Docker 経由です。`docker compose run --rm web npm install [pkg]` を使います。
