# UX チェックリスト（人手判定のみ）

機械で判定できる項目は `scripts/verify.sh` に移しました。この表には残った項目だけがあります。先に `verify.sh` を通し、通ってからこの表を実行します。

機械側が見ているもの: 任意値の色と寸法、フォーカス可視化、代替テキスト、動きの抑制、本文へのリンク、`lang`、`viewport`、min-width 変種、placeholder のラベル代用、`type="number"`、`autoComplete`、6状態の実装有無、理由なし無効化、共有部品の外側余白、トークン配置、`dangerouslySetInnerHTML`、3テーマのコントラスト、視覚回帰、LCP、CLS、操作対象の寸法、最小対応幅での横スクロール、内容の極端値での崩れ（入口画面の初期表示のみ）、バンドル寸法、lint、型、テスト、ビルド。

判定は「はい」「いいえ」「対象外」の3択です。「いいえ」が1つ以上あれば未完成として扱います。「対象外」は理由を記録します。理由のない対象外は「いいえ」と同じ扱いです。A 群は例外を認めません。

---

## A. 状態の中身（機械は存在しか見ていない）

- [ ] 空の状態が、何が入る場所かと最初の一歩を書いている
- [ ] エラーが、何が起きたか・なぜか・次に何をするかを平易な言葉で書いている
- [ ] 権限なしが、誰に依頼すれば使えるようになるかを書いている
- [ ] 部分取得が、失敗した範囲だけを再試行できる
- [ ] 実際に通信を失敗させて、楽観更新が元の状態へ戻り、失敗が利用者に伝わることを確認した
- [ ] 無効化の理由が、利用者が読んで次の行動を取れる内容になっている

## B. 時間の体感

- [ ] 画面遷移が1秒以内に表示される。超える場合は押下時に先に反応が返る
- [ ] 10秒を超える処理が同期的に待たせておらず、進捗が表示される
- [ ] 主要な単一作業が1分以内に完了できる
- [ ] 送信後の確認通知が1分以内に届く

## C. 伝達と一貫性

- [ ] 画面上の語彙に、内部実装の用語（テーブル名、ステータスの内部値、例外の文言）が漏れていない
- [ ] 開始した操作を中断する手段があり、見つけられる場所にある
- [ ] 同じ意味の操作が、画面をまたいで同じ語と同じ見た目になっている
- [ ] 一般的な慣習から外れていない。外れている場合は活動の理解を根拠にできる
- [ ] 損害の大きい誤操作が、制約または既定値または事前確認で予防されている
- [ ] 前の画面の情報を記憶している前提の画面がない
- [ ] 繰り返し使う操作にキーボードからの到達手段がある
- [ ] キーボードのみで全操作に到達でき、閉じ込められない
- [ ] 読み上げ順が視覚的な順序と一致している
- [ ] 画面上の要素すべてが、その画面の主要な目的を支えている
- [ ] 説明が必要な箇所で、必要な瞬間にその場に出ている

## D. ポインタ・キーボード・ウィンドウ

- [ ] 隣接する操作の間隔が `budgets.json` の `target.gapPx` 以上ある
- [ ] 破壊的操作が主要操作の隣に並んでいない
- [ ] hover だけで開示している表示がない（常時表示か、押下か、`:focus-within` でも開く）
- [ ] hover とフォーカスが別の見た目になっている
- [ ] 当たり判定が見た目と一致している
- [ ] 繰り返し使う操作にキーボード経路がある。単一キーの割り当ては入力中に無効化されている
- [ ] `tabindex` に正の値を使っていない
- [ ] スワイプできそうに見えてできない箇所がない
- [ ] 内容の末尾に次の移動先がある（行き止まりがない）
- [ ] 独自の「戻る」を追加していない
- [ ] 画面下端に固定した要素がない。ある場合は拡大時に内容を覆わないことを確認済み
- [ ] `viewport.reflowPx` の幅で、縦スクロールだけで内容と機能が失われない（SC 1.4.10）
- [ ] 文字を200%に拡大しても内容が失われない
- [ ] 入力経路のある画面へ上限いっぱいの文字列と最大桁の数値を実際に登録し、一覧・タイル・詳細が崩れない（機械検査は入口画面の初期表示しか見ていない）
- [ ] 対応ブラウザで確認した（ブラウザ名と版を記録する）

## E. フォーム

- [ ] 補足説明が入力欄の下にあり、訂正時にも同じ場所にある
- [ ] 対話窓で、入力欄と決定の操作が同時に見える範囲に収まっている
- [ ] 連続入力のフォームで、質問数を削る検討をした
- [ ] 非連続の更新で、全項目の入力欄を最初から展開していない
- [ ] 埋められる項目に既定値が入っている
- [ ] 入力補助が最初から書式を見せ、入力途中で書式が変わらない
- [ ] 自由入力の文字列と数値に上限がスキーマで定義され、超過の誤りが欄の直下に表示される
- [ ] 選択メニューが4回触れる操作に見合う場面でのみ使われている
- [ ] 登録を求める前に製品の価値を体験できる経路がある。ない場合は理由がある

## F. 日本語 UI

- [ ] 日本語入力の確定前に検索や検証が走らない
- [ ] 数値・電話番号・郵便番号が入力時に半角へ正規化される
- [ ] 氏名欄が姓名の分割を前提にしておらず、単一名の利用者を弾かない
- [ ] 表示する文字数の数え方が人の数え方と一致している
- [ ] 見出しと短い文言が不自然な位置で分断されていない
- [ ] 桁区切り・通貨・日付を自作せず `Intl` に任せている

## G. 文章

- [ ] 画面上の文章が、紙媒体で書く場合の半分以下の分量である
- [ ] 見出しがそこに何があるか分かる語になっている
- [ ] 各節が結論から始まっている
- [ ] ボタン、エラー、空状態、確認の文言も同じ基準を満たしている

## H. システム整合

- [ ] 部品が判断表に沿った層に置かれている
- [ ] 共有層の部品名が文脈と内容に依存していない
- [ ] 単発の部品を共有層に入れていない
- [ ] 「必要になるかもしれない」を理由に作った variant やトークンがない
- [ ] 部品固有トークンを新規に追加していない。追加した場合は理由がある

## J. 視覚設計

機械側は汎用パレット、`transition-all`、既定の影と角丸、グラデーション、絵文字、桁揃え、塗りボタンの重複を見ています。ここには判断が必要なものだけがあります。

- [ ] 外観プリセットが画面の性格に合っている（走査と入力が主目的なら実務型）
- [ ] 密な一覧や表の区画に `data-density="compact"` を当てている
- [ ] 基準幅で横方向が余っていない（縦一列に積んだままになっていない）
- [ ] 面には 1〜5、罫線には 6〜7、文字には 11〜12 を使っている（面に枠の段を使っていない）
- [ ] 部品の識別に境界が必要な箇所で `--edge-control` を使っている（装飾の罫線で代用していない）
- [ ] 塗り（9）を使っているのは主要操作と図形だけ
- [ ] 目の入口が1つある（同じ寸法・同じ色・同じ太さの要素が並んでいない）
- [ ] 見出しが役に対応した寸法・行間・字間になっている（すべて同じ寸法と太さになっていない）
- [ ] 太さが3段以内に収まっている
- [ ] 密度が用途に合っている（データ比較の画面に余白を取りすぎていない、読み物を詰めすぎていない）
- [ ] 間隔が刻みから選ばれており、関係のない要素が等間隔で並んでいない
- [ ] 見出しの上の余白が下より広く、どの段落に属するかが読める
- [ ] 区切り線を引く前に余白で分けられないか試した
- [ ] 通常・hover・押下・フォーカス・選択・無効・読込中が別物として描き分けられている
- [ ] フォーカスの表現が hover と兼用になっていない
- [ ] 動きの所要時間が対象の距離に対応している（すべて同じ値になっていない）
- [ ] アイコンの線幅と寸法が揃っている
- [ ] 単位や通貨が数値より1段落ちている
- [ ] 明色・暗色・高コントラストの3テーマで階層が保たれている

## K. 様式と印象

`references/visual-styles.md` 第5節の判定です。機械側はトークンを迂回した直書き、汎用パレット、グラデーション、絵文字、塗りの重複を見ています。色数の総数と角丸の種類数と影の段数は機械検査の対象外のため、ここに含めています。

- [ ] 目的・ターゲット・トーン（採用と回避）・様式が `[ux-plan]` に記録されている
- [ ] 選んだ様式が画面全体で一貫している（区画ごとに別の様式が混ざっていない）
- [ ] 回避すると決めた印象になっていない（`[ux-plan]` の回避欄と照合する）
- [ ] 彩度の高い色が画面面積の15%を超えていない
- [ ] 骨格の灰を除いた色数が4色以内
- [ ] 角丸が2種類以内（器の角丸と操作要素の角丸）
- [ ] 主題に `--fs-hero` が当たっており、見出しと本文の寸法差が2段以上ある
- [ ] 区画間の間隔が `--space-9` 以上で、区画内の間隔と明確に差がある
- [ ] Bento を選んだ場合、最大のカードと最小のカードの面積比が2倍以上ある
- [ ] 写真を使う場合、明度と彩度と画角が揃っている
- [ ] `visual-craft.md` 第13節の投資先のうち、上位3つ（主題の寸法・余白の非対称・面積の強弱）が実施されている

## L. 定型癖と文言の自己監査

`visual-craft.md` 第10-2節と第10-3節の照合です。生成する側の癖は生成した本人には見えないため、出荷前に必ず通します。

- [ ] 区画見出しの小ラベル（英大文字・広字間）が3区画に1つ以下
- [ ] 等幅3カラムのカード列を既定として使っていない
- [ ] 画像と文の左右交互が3回以上続いていない
- [ ] 同じ骨格の区画が3回以上繰り返されていない
- [ ] 装飾のための色付きドットがない（実際の状態を伝えるもののみ）
- [ ] スクロールを促す文言・矢印がない
- [ ] div 製の偽スクリーンショットがない
- [ ] 見本データに、見本と一目で分かる名や作り物めいた数値がない
- [ ] すべての可視文字列（見出し、ボタン、空状態、エラー、キャプション）を読み直した。文法の破綻、意味の通らない言い回し、過剰な比喩を書き直した
- [ ] 同じ意図の導線に別々の文言が併存していない（「お問い合わせ」と「ご相談はこちら」など）
- [ ] すべての動きについて、何を伝えるか（階層・フィードバック・状態遷移・物語）を1文で言える
- [ ] `DESIGN.md` の Do's and Don'ts に違反していない

## I. 誠実さ

- [ ] 実際には進んでいない進捗表示がない
- [ ] 意味のない待機演出がない
- [ ] 成功したように見せて後で失敗する箇所がない
- [ ] 実際の機能より優れて見せる表現がない
- [ ] アニメーションと装飾が、操作の理解を助ける場合にのみ使われている
