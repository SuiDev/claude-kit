# インターフェース棚卸しテンプレート

既存の界面を持つプロジェクトで、整備の前に実施します。設計の考え方は `references/design-system.md` 第3節にあります。

## 進め方

| 段階 | 時間 | 内容 |
|---|---|---|
| 1. 招集 | — | 設計・実装・企画・品質保証・事業側・内容を書く人を集める。1人で進めると語彙の統一という最大の成果が得られない |
| 2. 準備 | 10分 | 全員が同じ道具を使うことに合意する（後で1つにまとめるため）。カテゴリを担当に割り当てる |
| 3. 取得 | 30〜90分 | すべての出現箇所ではなく、異なる表現を1つずつ取得する。時間で区切る |
| 4. 発表 | 各10〜15分 | カテゴリごとに発表し、名称と根拠を議論する。同じものを職種ごとに違う名で呼んでいる事実がここで露わになる |
| 5. 決定 | — | 残す・捨てる・統合する部品、確定する名称、次の手順を決める |

網羅より、統一されていない事実の可視化を優先します。取得漏れは次回の棚卸しで拾います。

## カテゴリと記入欄

各カテゴリで、見つけた異なる表現の数と、確定した名称、置き場所の層を記録します。層の判断は `references/design-system.md` 第2節の表に従います。

| カテゴリ | 見つけた表現の数 | 確定した名称 | 層 | 残す / 捨てる / 統合 |
|---|---|---|---|---|
| 全体要素（ヘッダー、フッター） | | | | |
| ナビゲーション（主ナビ、フッターナビ、ページ送り、パンくず、部品内操作） | | | | |
| 画像の種類（ロゴ、主画像、アバター、縮小画像、背景） | | | | |
| アイコン（検索、共有、矢印、メニュー、読込中、ファビコン） | | | | |
| フォーム（入力欄、複数行、選択、チェック、切替、ラジオ、スライダー） | | | | |
| ボタン（主、副、大、小、無効、押下中、読込中、文字リンク風） | | | | |
| 見出し（h1〜h6 と変種） | | | | |
| ブロック（見出しと画像と要約の組み合わせ） | | | | |
| リスト（順序あり、順序なし、定義、罫線、縞） | | | | |
| 対話部品（アコーディオン、タブ、カルーセル） | | | | |
| メディア（動画再生、音声再生） | | | | |
| 外部埋め込み（ウィジェット、iframe、外部ボタン、計測用スクリプト） | | | | |
| 広告（全形式と寸法） | | | | |
| 通知（警告、成功、エラー、確認中、ポップアップ、ツールチップ、404） | | | | |
| 色（界面に現れるすべての固有色） | | | | |
| 動き（画面録画で取得する） | | | | |

通知は利用者の操作なしに出ないものが多く、取得が難しいカテゴリです。同時に最も差が出やすいため、意識して集めます。

## 集計後にやること

1. 確定した名称を `references/design-system.md` 第10節の命名規則で点検する（文脈と内容に依存していないか）。
2. 層ごとに `scripts/scaffold.sh` の骨格へ配置する。
3. 色は `assets/ui-baseline.md` のトークンへ寄せ、任意値を残さない。
4. `scripts/ux-lint.sh` を通して、任意値の色と共有部品の外側余白が残っていないことを確認する。
